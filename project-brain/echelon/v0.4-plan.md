# echelon — v0.4 Plan

## Purpose

v0.3 established a stronger synthetic claim:

- the debugging-core result survived a first adversarial pass

v0.4 exists to test whether that result is still real when we push on broader failure modes without broadening the product.

This is still a debugging-only control-systems experiment.

## Core question

Can routed debugging policy survive stronger anti-bias tests without collapsing into:

- benchmark-shaped search behavior
- hidden preference for exploration
- dependence on weak baselines
- overfitting to hand-authored synthetic worlds

## Build order

### 1. Permutation invariance

Purpose:

- verify that labels, family naming, and action ordering are not carrying the result

v0.4 expectation:

- preserve the current `v0.3` permutation test
- expand it if needed to cover more than one remapping pattern

Fail if:

- routed wins disappear under simple renaming or reorderings

### 2. Anti-broadening trap suite

Purpose:

- prevent the benchmark from rewarding adaptive drama when simple narrowing should win

This suite should include cases where:

- `fixed_heuristic` ought to win
- exploration is wasteful
- early broadening burns budget
- the correct move is simple pruning, not mode-switching
- overactive transitions create worse outcomes than restraint

Fail if:

- routed only wins on router-friendly worlds
- routed loses badly whenever the best move is simple narrowing

### 3. One stronger baseline

Purpose:

- make sure the wedge is stronger than “beats toy baselines”

Recommended baseline:

- an information-gain or score-threshold baseline

Characteristics:

- uses the same action space
- does not have routed transitions
- is still simple enough to inspect and explain

Fail if:

- routed only beats `naive_retry`, `always_compound`, or other weak baselines
- routed cannot beat one stronger non-trivial baseline on the focused suite

### 4. Generated hidden holdout

Purpose:

- test whether routed performance survives outside the hand-authored development set

Requirements:

- generated from unseen seeds
- hidden truth remains evaluator-only
- router sees only visible context
- cases are not tuned during development

Fail if:

- routed advantage collapses on the generated holdout
- tie rate dominates and the synthetic win turns out to be brittle

## Metrics

Primary:

- success under budget
- repeated failed-path suppression
- cost before decisive root-cause signal
- dead-end persistence

Secondary:

- transition count
- hysteresis
- score delta versus stronger baseline

## Anti-bias rules for v0.4

- do not add new regimes
- do not broaden to new domains
- do not tune against the generated holdout
- do not accept wins that come only from weird synthetic ordering artifacts
- do not let the stronger baseline secretly become weaker than `fixed_heuristic`

## Decision rule

v0.4 is promising if:

- routed remains stable under permutation
- routed performs credibly on anti-broadening traps
- routed beats one stronger baseline on the focused suite
- routed retains an advantage on generated hidden holdout cases

v0.4 fails if:

- the result only holds on hand-authored router-friendly cases
- stronger baselines erase the claimed advantage
- generated holdout performance collapses

## Interpretation

If v0.4 passes, the claim becomes materially more serious:

- adaptive search-policy control may have a real debugging wedge

If v0.4 fails, that is still useful:

- it tells us the current result is narrower or more benchmark-shaped than hoped

That is the right scientific posture for this stage.
