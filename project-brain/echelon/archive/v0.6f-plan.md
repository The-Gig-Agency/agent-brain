# Echelon — v0.6f Plan

## Goal

`v0.6f` is not about more replay volume.

It is about **harder asymmetry** and **less direct terrain leakage**.

The target question is:

> Can the router still separate explore from prune when both sides contain noise and the visible layer reads more like issue text, logs, and repro notes than like hand-labeled terrain?

## Why v0.6f Exists

`v0.6e` was the first mixed replay pack with a real regime boundary.

But it still had two weaknesses:

1. the explore side carried more explicit ambiguity shaping than the prune side
2. the terrain inference still leaned too much on direct string triggers and evaluator-shaped phrasing

`v0.6f` is the first pass that tries to tighten both at once.

## Design Rules

- keep the domain narrow: debugging only
- keep the router simple: same small regime set
- do not expand model complexity
- add noise to **prune** cases too, not just explore cases
- include at least one explore case with weaker explicit ambiguity shaping
- reduce direct phrases like `response-shape mismatch` and `nested response format` in the visible layer
- express visible evidence more like:
  - issue text
  - repro notes
  - ambiguous logs
  - partial observations

## What Makes This Harder

### Harder explore side

- one weaker-signaled explore case (`ciq-6adf83e`)
- less direct terrain phrasing
- context assembly and fallback ambiguity instead of explicit “hidden dependency” labels

### Harder prune side

- distracting refresh logs
- misleading auth surface
- upstream data present even though local mapping is wrong
- stale-state-looking symptoms that still resolve through compact local fixes

## Pass Condition

`v0.6f` should pass only if:

- routed match rate stays above both compact baselines
- at least one noisy prune case remains correctly classified as `prune`
- at least one weaker-signaled explore case remains correctly classified as `explore`

## What v0.6f Still Does Not Do

- full execution-grounded patching
- environment-shift or mid-search reversal scoring
- compound-deserving replay cases
- raw naturalistic incident capture without evaluator shaping

## If v0.6f Works

Then the next move should be:

1. anti-transition or strategy-reversal replay cases
2. confidence-rise-then-collapse cases
3. environment-shift cases

Not:

- more ontology
- more agents
- more generic orchestration abstraction
