# Echelon — v0.7 Operational Realism Plan

## Goal

`v0.7` is the first benchmark layer built around the objection that current replay packs still assume too much operational coherence.

The target question is:

> Can adaptive commitment control still improve search quality when truth is partial, evidence is contradictory, and the environment does not stay stable long enough for one clean root-cause story?

This is a different question from `v0.6d` through `v0.6f`.

Those passes test whether routed search helps on **recoverable but noisy incidents**.

`v0.7` should test whether routed search still helps when incidents are only **partially recoverable, multi-causal, shifting, or containment-oriented**.

## Why v0.7 Exists

Current replay phases are meaningfully stronger than the early work:

- more discriminative
- less fingerprintable
- more symmetric
- less direct in their terrain wording

But they still usually assume:

- a coherent root cause exists
- that root cause is recoverable
- evidence eventually resolves into a stable story
- the environment stays stable enough for one correct regime to emerge

Real incidents often violate all four at once.

`v0.7` should not pretend those failures are edge cases.

It should make them part of the benchmark.

## Scope

- keep the domain narrow: debugging and incident response only
- keep the regime set small: `explore`, `prune`, `compound`, `check`
- do not expand into generic orchestration or broad agent frameworks
- do not expand model count yet
- preserve router-visible versus evaluator-only separation

## New Incident Classes

### 1. Underdetermined Incidents

Cases where more than one explanation remains plausible even after investigation.

Desired behavior:

- avoid false certainty
- avoid overcommitting to one branch too early
- switch from “find the one truth” to “bound uncertainty and reduce blast radius”

### 2. Multi-Causal Incidents

Cases where one local fix helps but does not fully resolve the problem.

Desired behavior:

- recognize partial improvement as partial, not final
- preserve exploration budget after a first apparent fix
- avoid premature compounding

### 3. Environment-Shift Incidents

Cases where the terrain changes mid-search.

Examples:

- a background task changes state while debugging
- a deploy lands
- retries alter the environment
- the initial evidence becomes stale

Desired behavior:

- detect drift
- downgrade confidence when the old frame stops fitting
- re-open the search when the world changes

### 4. Contradictory-Evidence Incidents

Cases where logs, metrics, and visible symptoms conflict.

Desired behavior:

- resist overfitting to one evidence channel
- use cross-checking or containment rather than theatrical mode-switching
- prefer safe narrowing over fragile confidence

### 5. No-Clean-Win Incidents

Cases where success is not “found the one bug.”

Success may instead mean:

- reduced blast radius
- bounded uncertainty
- safer rollback or fail-closed state
- better next-step prioritization

Desired behavior:

- optimize for search quality and operational safety, not just semantic correctness

## What Changes In Evaluation

`v0.7` should not rely only on:

- hidden expected regime match
- compact baseline comparison

Those stay useful, but they become insufficient.

### New Metric Families

#### 1. Overcommitment Regret

Measures whether the router commits too strongly when the incident does not justify certainty.

Examples:

- confident pruning on a genuinely underdetermined case
- compounding after only partial evidence

#### 2. Containment Quality

Measures whether the system reduces risk or blast radius even before full resolution.

Examples:

- choosing fail-closed behavior
- preferring bounded rollback over unsafe apparent success

#### 3. Confidence Collapse Quality

Measures whether the system can lower confidence appropriately when new evidence breaks the current story.

Examples:

- confidence rises after a plausible local fix
- later evidence contradicts it
- router re-opens search rather than rationalizing

#### 4. Drift Recovery Cost

Measures how expensive it is to recover after the environment shifts.

Examples:

- steps wasted after the terrain changed
- cost between drift onset and corrected regime

#### 5. Partial-Resolution Handling

Measures whether the system treats partial fixes as partial.

Examples:

- first symptom improves but deeper inconsistency remains
- router avoids calling the search “done” too early

## Dataset Design Rules

- visible layer should read like issue text, repro notes, partial logs, and time-ordered observations
- avoid explicit terrain labels
- include some cases where decisive evidence never fully appears
- include some cases where the hidden evaluator truth is a **set of acceptable containment moves**, not one perfect answer
- include time-ordering or phase changes where needed to represent drift

## Example v0.7 Pack Shape

Initial target:

- 2 underdetermined incidents
- 2 multi-causal incidents
- 2 environment-shift incidents
- 1 contradictory-evidence incident
- 1 no-clean-win containment incident

This keeps the pack small while making the realism objection concrete.

## Pass Condition

`v0.7` should pass only if:

- routed policy still beats compact baselines on at least one new realism metric family
- router avoids obvious overcommitment on underdetermined cases
- router recovers from at least one environment-shift case without collapsing into thrash
- router handles at least one partial fix as partial rather than final

## What v0.7 Would Prove

If successful, `v0.7` would not prove full production readiness.

But it would prove something more important than current phases:

> the router is not only a recoverable-noise classifier; it has some value when operational truth is unstable, incomplete, or multi-causal

## What v0.7 Still Would Not Prove

- full autonomous incident response
- broad cross-domain generalization
- that one ontology covers all operational reality
- that the router can replace human judgment in ambiguous incidents

## Best Next Move

Build `v0.7` as a new evaluation layer, not as a cosmetic extension of `v0.6f`.

That means:

1. add explicit realism-case schemas
2. add new metric fields for containment, overcommitment, and drift recovery
3. mine a very small real-case pack that actually exhibits unstable truth
4. only then compare against current compact baselines again
